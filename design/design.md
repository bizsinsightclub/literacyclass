# design.md — 레이아웃 규칙 & 카테고리 매핑 플레이북

> 이 문서는 `Re-Cheil` 파이프라인의 **레이아웃 결정 규칙**이다.
> Documenter 단계와 `deck-builder` 스킬이 **장표 내용 → 레이아웃 카테고리**를 매핑할 때 참조한다.
> 성공 기획안(레퍼런스 덱) 관찰에서 도출한 7개 카테고리를 정리하고, 사용자 수정으로 지속 고도화한다.

---

## 0. 단일 진실원천 (SSOT) 원칙 — 중복 정의 금지

- **폰트·웨이트·크기 토큰·컬러·자간/행간·체크리스트는 전부 `design/Cheil_Design.md`가 단일 진실원천**이다.
- 본 문서는 그 토큰을 **참조만** 한다. 같은 값을 다시 정의·복제하지 않는다(드리프트 방지).
- 본 문서 고유 책임 = **레이아웃 카테고리의 "언제 쓰나 / 구성요소 / 권장 폰트·크기·정렬 / 예시" 정리**와 **내용→카테고리 매핑 결정 로직**.
- 토큰 출처 참조 표기:
  - 폰트 패밀리·화이트리스트 → `Cheil_Design.md §1, §2.3`
  - 타입 위계·18pt 분기·7pt 하한 → `Cheil_Design.md §3`
  - 크기 스케일(Display/Subhead/Body/Caption/Graphic) → `Cheil_Design.md §1(size_pt), §4`
  - 정렬 규칙(좌/중앙 기본) → `Cheil_Design.md §4, §1(align)`
  - 컬러 팔레트 토큰 → `Cheil_Design.md §7`
  - 자간/행간(폰트 내장값, 임의 변형 금지) → `Cheil_Design.md §5`
  - 강제 체크리스트(BLOCK/WARN) → `Cheil_Design.md §10`
- 권위 등급은 Cheil_Design.md와 동일: `[PB] > [USER] > [DECK]`. 본 카테고리 정의의 근거는 `[DECK]`(레퍼런스 덱 §8).

## 1. 사용법 (에이전트가 이 문서를 소비하는 법)

1. 먼저 `Cheil_Design.md §1 Quick Reference`를 로드해 토큰을 확보한다(본 문서는 토큰을 재정의하지 않음).
2. 장표 1장의 **내용 유형**을 §3 결정 트리에 넣어 카테고리를 1개 선택한다.
3. 선택한 카테고리의 §4 카드에서 **구성요소·권장 폰트/크기/정렬**을 그대로 분기 로직으로 적용한다.
4. 적용 후 `Cheil_Design.md §10 체크리스트`로 BLOCK/WARN을 검사한다(특히 `[STAT-SRC]`, `[FONT]`, `[SIZE-MIN]`).
5. 매핑 판단 근거는 `state/decisions.json`(디자인 선택 기록)에 남긴다(`CLAUDE.md §7`).

## 3. 내용 → 카테고리 결정 트리 (deck-builder 분기용)

```
# 입력: 장표 1장의 핵심 내용 유형
if 장표 == 문서 첫 장(타이틀/주제/날짜만):              → 1. Cover
elif 핵심이 '대형 수치/비율/금액(%, B, 배수 등)':        → 5. Data / Stat   # 출처 캡션 필수
elif 핵심이 '한글 문학·감성 인용(서정적 문장)':          → 7. Literary / Quote
elif 목적이 '독자에게 질문 던지기/문제 제기':            → 2. Question / Hook
elif 목적이 '섹션 경계 전환(챕터/단계 라벨)':            → 3. Section Divider
elif 핵심이 '단일 개념어/메시지 1개를 크게 앵커':        → 4. Big-Statement
elif 핵심이 '복수 이미지/사례/인물/제품 나열':           → 6. Image-grid / 비주얼
else:                                                  → 4. Big-Statement  # 기본 폴백
```

- 한 장표는 **카테고리 1개**에 매핑한다. 혼합 필요 시 장표를 분할한다.
- 수치가 1개라도 핵심이면 Data/Stat을 우선(출처 강제 정합). 수치가 부차적이면 본문에 배치하고 다른 카테고리 유지.
- 한글 본문이면 §4 각 카드의 폰트를 `*_KR` 패밀리로 치환한다(`Cheil_Design.md §3.2`).

## 4. 카테고리 카드 (언제 쓰나 / 구성요소 / 권장 폰트·크기·정렬 / 예시)

> 모든 크기·폰트 표기는 `Cheil_Design.md §1·§3·§4`의 토큰을 **참조**한 것이다(본 문서가 정의한 신규 값 아님).

### 4.1 Cover (표지/타이틀)
- **언제 쓰나**: 문서/덱의 첫 장. 주제·타이틀만 전달, 정보 과밀 금지.
- **구성요소**: 초대형 헤드라인 + 최소 보조 요소(부제·날짜·출처주체). 이미지 없음.
- **권장 폰트/크기/정렬**: Head Bold(또는 의도적 Head Light) · Display **96pt** · 좌측 또는 중앙(`Cheil_Design.md §1 align`).
- **예시**: 레퍼런스 덱 S01 `[DECK]`.

### 4.2 Question / Hook (질문 던지기)
- **언제 쓰나**: 독자에게 문제·질문을 제기해 주의를 끌 때.
- **구성요소**: 큰 질문문 + `Q.` 마커.
- **권장 폰트/크기/정렬**: Head Medium~Bold · Subhead/Display **32–44pt** · 좌/중앙.
- **예시**: S02·S06·S09 `[DECK]`.

### 4.3 Section Divider (섹션 전환)
- **언제 쓰나**: 챕터·단계 경계 전환.
- **구성요소**: 섹션명 + 초대형 장식 번호(**≈199pt**, 본문 텍스트 아님) + 단계 라벨.
- **권장 폰트/크기/정렬**: Head 계열 · 번호 Graphic **199pt** · 좌/중앙. 199pt는 장식 전용(`Cheil_Design.md §4 Graphic`).
- **예시**: S20·S30·S36 `[DECK]`.

### 4.4 Big-Statement (모티프 앵커)
- **언제 쓰나**: 핵심 개념어/메시지 1개를 크게 강조. 결정 트리의 기본 폴백.
- **구성요소**: 단일 개념어 + 주변 소형 텍스트. 반복 앵커(모티프) 패턴 허용.
- **권장 폰트/크기/정렬**: Head Light 또는 Bold · Display **54–60pt** · 좌/중앙. Head Light는 의도적 대형 헤드라인에만(`Cheil_Design.md §9.1`).
- **예시**: S04·S05·S13–17 `[DECK]`.

### 4.5 Data / Stat (데이터·수치 제시)
- **언제 쓰나**: 비율·금액·배수 등 대형 수치가 핵심일 때.
- **구성요소**: 대형 수치(예 70%·63%·37B) + **소형 출처 캡션**.
- **권장 폰트/크기/정렬**: 수치 Head **54pt** + 출처 캡션 **10–12pt** · 좌/중앙.
- **강제**: 모든 수치에 출처 캡션 병기 → `Cheil_Design.md §10 [STAT-SRC]`(누락 시 **BLOCK**). 본 프로젝트는 `[S#]` 식별자를 캡션에 함께 표기한다(`CLAUDE.md §1.3`).
- **예시**: S07·S08·S18 `[DECK]`.

### 4.6 Image-grid / 비주얼 (사례·인물·제품)
- **언제 쓰나**: 복수 사례·인물·제품을 나열·비교.
- **구성요소**: 다중 이미지 + 라벨.
- **권장 폰트/크기/정렬**: Body/Head 캡션 **14–24pt** · 좌/중앙.
- **예시**: S24·S27·S37 `[DECK]`.

### 4.7 Literary / Quote (문학·감성 인용)
- **언제 쓰나**: 한글 문학·감성 인용을 정서적으로 제시.
- **구성요소**: 한글 문학 인용을 **세리프(ChosunilboNM)**로, 구조/정보 텍스트(Head)와 대비.
- **권장 폰트/크기/정렬**: ChosunilboNM · 본문~**44pt** · 좌/중앙.
- **제약**: ChosunilboNM은 **비공식·문학 인용 한정**. 정보·구조 텍스트는 반드시 Samsung SS(`Cheil_Design.md §9.1`).
- **예시**: S25·S37 `[DECK]`.

## 5. 공통 레이아웃 규칙 (전 카테고리)

- **정렬**: 좌측·중앙 기본. 우측·하단은 의도적 소수 사용(`Cheil_Design.md §4`).
- **자간·행간**: 폰트 내장 메트릭만 사용, 임의 트래킹/행간 변형 금지(`Cheil_Design.md §5`).
- **컬러**: 기본 톤 = `--color-bg`(검정) 배경 + `--color-fg`(흰) 텍스트. **모노톤 최소** — 강조는 포인트 1색(민트)만 극소량, 위계는 색이 아닌 크기·웨이트·여백으로(`Cheil_Design.md §7.3`).
- **위계**: 헤드라인 vs 부제는 크기·웨이트로 충분히 구별(과유사 시 `[HIER]` WARN).
- **한글**: 모든 한글 텍스트는 `*_KR` 패밀리로 치환(`[FONT-KR]`).
- **장표 당 카테고리 1개**: 혼합 시 분할. 매핑 결과는 `state/decisions.json`에 기록.

## 6. 고도화 루프 (Lesson.md → 본 문서 반영 절차)

> `CLAUDE.md §7`: 사용자의 모든 수정은 `design/Lesson.md`에 누적 → 주기적으로 본 파일에 반영.

1. **수집**: 사용자 디자인 수정·피드백이 발생하면 즉시 `design/Lesson.md`에 `[일자/장표·카테고리/수정내용/사유]` 형식으로 1건씩 append.
2. **분류**: 누적 항목을 (a) 레이아웃 규칙(본 문서 대상) / (b) 토큰 변경(`Cheil_Design.md` 대상)으로 분류.
   - 토큰(폰트·크기·컬러·자간) 변경은 **반드시 `Cheil_Design.md`에서만** 수정한다(SSOT 불변). 본 문서는 그 토큰을 참조만.
3. **반영 주기**: Lesson.md 누적 **3건 이상** 또는 한 사이클(덱 1건 완성) 종료 시 반영 패스를 1회 수행.
4. **반영 작업**:
   - 레이아웃 규칙 변경 → 본 문서 §3 결정 트리 또는 §4 카드 갱신.
   - 새 패턴이 기존 7개 카테고리로 분류 불가할 경우, **임의 추가 금지** → 사용자에게 카테고리 신설 여부 에스컬레이션(Cheil_Design.md §8과의 1:1 유지).
5. **추적성**: 각 반영은 본 문서 §7 변경 이력에 `[일자/반영한 Lesson 항목/변경 요지]`로 1줄 기록하고, 반영 완료한 Lesson.md 항목에 `반영완료(design.md §X)` 마킹.
6. **분리 원칙**: 작성/반영 패스와 검토 패스는 분리한다(자기승인 금지, `CLAUDE.md` 운영 원칙). 반영 후 매핑 정확성 검토는 별도 패스로 수행.
